# End-to-end evaluation of Athena (Oct 28, 2026)

Method: five read-only reviews by specialist agents (architecture, data pipelines and operations, speed, LLM workflows and ML, security and correctness), each told not to run anything, open any database or read the secrets file. Their findings were consolidated here. I spot-checked three of the highest-impact claims in the code (marked **verified**); everything else is the reviewers' reading of the code and is marked **reported** until it is fixed and tested. Speed figures are estimates, not measurements. Nothing was changed by this review.

## Verdict

- The system is sound at its core: the model never does arithmetic, replies are checked against a facts sheet, extraction proves itself against the exchange's own figures, the order desk fails closed, and the studies say honestly what they cannot show.
- The weak points are not speed of the live feed (it is fine) but **operations** (nothing tells you a job died; jobs collide; failures are retried forever), **the model layer** (a dead provider is half-hidden and wasteful), **evaluation** (the harness cannot yet measure agent skill honestly) and **a few small correctness gaps** in the order desk and the blend.
- Almost none of it is trained machine learning. It is LLMs used as checklist readers, extractors and phrasers, plus rules and classical statistics. With the sample sizes available, adding trained models would fit noise (see "Ruled out").

## DO NOW (small, high payoff)

| # | Finding | Evidence | Effort |
|---|---|---|---|
| 1 | **Nothing tells you a background job died, and nothing stops two jobs colliding.** Only the warehouse build writes a status file. Ingest, documents, holdings and annual-report jobs print to a log; two of them crashed unnoticed (lock, then a Windows resource error). No file lock exists, and the exchange throttle is per process, so two parallel NSE jobs double the request rate. Fix: a small `athena.ops` module: a job wrapper writing `.athena/status/<job>.json` (pid, heartbeat, last error, progress) with two lock files (one NSE fetcher at a time; one long writer per DuckDB file), and `python -m athena.ops check` printing one verdict. | reported (ingest/runner/store; the crashes themselves are in logs) | M |
| 2 | **The job loop dies on any error except an exchange block**, and the fundamentals store gives up on a locked file after 4 s (the warehouse waits 120-300 s). Fix: catch per company, record "failed" with the reason and go on, stop after N store errors in a row, wait longer for the lock, retry a transient write error, open the store once per company rather than 3-4 times per filing. (I already made the annual-report job survive a damaged archive.) | reported (`runner.py:39-45`, `store.py:54`) | S |
| 3 | **The stall detector mislabels failures and blocks the wrong jobs.** An LLM outage printed "no reply from the exchange for 5 companies" and wrote a block row that pauses every exchange job for 5 minutes. Count only exchange errors toward a stall; give block rows a per-job key. | **verified** in `logs/annual-nifty500-3.log` | S |
| 4 | **Failed items are retried forever, with duplicate downloads and model spend.** Fetch failures are not recorded (so dead URLs are asked again on every resume); annual reports (up to 80 MB) are re-downloaded each retry although the reader has a cache folder it never uses; deterministic failures repeat (29 "all sources failed", 11 "unknown unit lacs", 4 damaged archives, 3 too large). Fix: negative cache with retry-after, cache PDFs by hash, record the per-report outcome, and run one trivial model call before a long model job so a withdrawn model aborts at once. | reported | S-M |
| 5 | **Freshness and coverage are not enforced on the data stores.** `freshness`, `canary` and `coverage` are used by the agents only; no job runs them. Prices older than 3 days with no file are recorded as "no session" permanently (a transient 404 is never retried), and derivs does the same. Fix: read-only gates in `athena.ops check`: every no-session day must be a known exchange holiday; last-day symbol count and prices sane; derivs last day equals the warehouse's; companies past their results date have a newer filing; latest-quarter shareholding coverage at least 95% after the deadline; zero duplicate statement keys. This retires most manual checking. | reported (`ingest.py:48-66`, `bhavcopy.py:150`) | M |
| 6 | **A dead model provider is half-hidden and wasteful.** A 429 "no credits" is treated as retryable (3 tries and sleeps per call, and OpenAI heads the judge tier); degraded-model memory is per process, so each subprocess re-hits dead models; failed attempts and the answering model are not logged or stored in the verdict; no overall deadline; a truncated (length-limited) reply is accepted. Fix: classify quota errors as non-retryable, persist degraded state with an expiry, log failures and the answering model into the usage log and the verdict payload, drop dead entries from the tiers. | the 429 retry is **verified** in `llm/client.py`; the rest reported | S-M |
| 7 | **Order desk is not safe against two things at once.** Redeeming a token, appending to the audit log and saving the paper account have no file lock, so two simultaneous confirms could both place and the audit chain could report false tampering. Harmless in paper, a double real order once a live adapter exists. Fix: one OS file lock around redeem, check, place and audit append; write files via temp file and replace. | **verified** (no lock anywhere in `brokers/`) | S |
| 8 | **The paper desk trusts any quote.** It ignores the quote's source and timestamp, so a polled (delayed) price, a holiday last close or a fake-feed terminal can fill a paper order and make P&L look real. Fix: require a streamed quote within about 5 s and refuse if the feed is off or fake. | reported (`quotes.py:16-22`) | S |
| 9 | **The terminal API accepts requests with no Origin header**, and some GET routes spend credits or subscribe contracts (for example the sentiment tone reading). A web page you visit could trigger them blind. Fix: require `Sec-Fetch-Site` same-origin or a per-launch token; add CSP and `frame-ancestors 'none'`. Do this before any order button exists. | reported (`server.rs:82-85`) | S |
| 10 | **Symbol validation lets a leading `-` through to a command line.** Flag confusion, not code execution. Fix: first character alphanumeric, or `--` before the argument. | reported (`server.rs:118`) | S |
| 11 | **The blend lets one weak analyst produce a "Buy".** `net` is divided by total weight, so a single bullish analyst at confidence 20 gives net +1.0 and the verdict word "Buy" (conviction is then low, which partly hides it). Fix: divide by the number of participants so weak or lone calls land near Hold; enforce the prompt caps (for example ownership confidence at most 40) in code. | **verified** (`orchestrator/blend.py`) | S |
| 12 | **The agent evaluation harness has holes.** `--repeats 3` re-asks the same cached question, so run agreement is meaningless; rows do not log the model, prompt hash or packet hash (a mid-run fallback is an invisible confound); one path bypasses the call ceiling; the model's own memory of 2024-26 prices is the biggest leak. Fix: bypass the cache for repeats, log hashes, run blinded and unblinded on the same cases (the gap measures memorisation). | the in-memory cache is **verified** (`agents/base.py:93`); the rest reported | S |
| 13 | **Replies are cached before they are validated**, so a malformed reply sticks for a week; and some models get no temperature, so the "temperature 0" assumption is false for them. Fix: cache validated outputs keyed with the model and prompt version. | reported (`llm/cache.py:87`) | S |
| 14 | **Annual-report extraction checks too little per line.** A whole earlier year is kept once the overlap year agrees on 80% of lines, and only three identities are checked. | 16 | **Speed: Fundamentals and Valuation pages open the 405 MB warehouse on the async thread on every call, even on a cache hit**, only to read a price; if the file is write-locked the page silently loses market cap and P/E. ## LATER (worth it, but not now)

- **Event-driven fetching** instead of full sweeps: a resume sweep over about 3,400 symbols costs about 3 hours just to learn there is nothing new. Fetch a company when its results date has passed; holdings only after quarter-end; documents in tiers. A missed event is caught by gate 5. Test whether the exchange has a bulk announcements call first (not verified).
- **Point-in-time loss in the fundamentals store.** A restated period deletes the earlier-filed row, so "what did the market know on date X" is lost for restated figures (the raw XML cache can rebuild it). Make rows append-only and read the latest row filed on or before the as-of date; wrap each filing's write in a transaction now (small).
- **Merge the Python spawn patterns** (8 spawn sites, 3 patterns) into one sidecar protocol with a separate pool for the heavy analyse worker and a cancel for long jobs.
- **One owner for the Angel One session** (three separate logins exist; a second login may invalidate the first - not verified against Angel's rules). Needs your sign-off.
- **Order desk before any live adapter** (hard prerequisites): a human confirm that is not a command-line argument; a keyed audit chain or an external anchor; limits pinned by hash or file permission; remove the unused Kite listen code; store the TOTP seed and PIN in Windows Credential Manager; atomic write of the settings file.
- **Calibration** should require a bootstrap confidence interval above zero and shrink trust by sample size (today it can flip to "calibrated" by noise at n of 300).
- **Studies** are too small to see a real edge (valuation: 6 dates; ownership: about 9 quarters). They can reject only large skill (minimum detectable rank IC about 0.08-0.10 at roughly 12 independent dates). The 2016+ annual-report history will help more than more stocks. Reword the personas from "found no link" to "not shown to help".
- **Council:** keep it opt-in. Seven agents of one model family plus a judge fire only on conflict (tens of cases), so "promote only if it wins" cannot be tested. A cheaper, testable design is deterministic scores per checklist plus one model pass to narrate (about 1 call a stock instead of 6-9).
- **Dependencies:** no Python lock file; unofficial or fragile packages (jugaad-data, yfinance, xlrd, TA-Lib build); run pip-audit, cargo audit and npm audit (not run yet; waiting on your approval to install).
- **Atomic writes** for the notebook, formulas and strategies files; host allow-list for URLs taken from exchange JSON; size cap on unzipped reports.
- **Smaller speed items:** unbounded bars cache and no single-flight; sentiment starts a cold Python each time (about 1 s); `known` and `analysis` open the warehouse on each symbol change.

## Ruled out (not worth the trade-off now)

- **Trained machine learning** (ridge, gradient boosting, calibrated confidence): about 40-2,000 stocks with at most 5 years of fundamentals, overlapping windows and a null result on every feature means it would fit noise. Revisit only after the long history is in, under walk-forward and variant-count rules.
- **Moving DuckDB to Parquet for serving**, a single-writer daemon, or Airflow: writes take milliseconds and the network is the bottleneck; locks plus a sequential runner give the same safety. Parquet is for backups only.
- **Rewriting the Rust REST layer into Python (or the reverse):** the split is justified (Rust for the stream and bars hub, Python for the libraries, TypeScript for the browser). A rewrite would delete the helper protocol but add a hop.
- **Front-end bundle (942 KB JS) and gzip:** transfer is on loopback; the saving is under about 150 ms once. Skip unless it is slow.
- **Hardening the Python indicators into a true sandbox:** theoretical on an owner-only machine; revisit only if you ever run indicators written by others.
- **Screen cache clone cost, ART indexes in DuckDB, retiring the Streamlit dashboard:** small or an owner decision.

## Already sound

The model never does arithmetic and replies are rejected if a number is not on the sheet; annual-report extraction proves itself before storing; studies state their own limits; fallback from warm helper to cold run is byte-identical; Host and Origin checks stop DNS rebinding and cross-site writes; no `innerHTML`, `eval`, `pickle`, `shell=True` or string-built SQL was found; XML is parsed with `defusedxml`; the order desk fails closed (limit-only, long-only, hashed one-use tokens, every rule re-checked at confirm); the warehouse build writes a status file and last ran clean on Oct 27 in 17 minutes; the live feed's own latency is not the problem.
