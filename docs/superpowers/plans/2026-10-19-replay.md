# Bar replay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replay a chart bar by bar from a chosen bar with no look-ahead, in the Chart Lab and synced across the Grid.

**Architecture:** A pure `chartlab/replay.ts` (bar end, revealed prefix, speeds, the player's state machine). `ChartModel` holds the full bars and a replay cursor, and exposes the revealed prefix as `bars`. `ChartLabView` gets the Replay button, start picking, controls and keys; `GridView` follows by moment.

**Tech Stack:** TypeScript, Lightweight Charts v5, vitest, Playwright.

## Global Constraints

- Spec `docs/superpowers/specs/2026-10-19-replay-design.md`.
- A chart shows a bar only when it has ended by the replay moment.
- Nine speeds: 0.1, 0.33, 1, 2, 3, 5, 10, 20, 50 bars a second; default 1.
- Live prices never move a replaying chart; replay is not kept between visits.
- A chart not replaying behaves exactly as before.

## As built (2026-10-19)

Tasks A to E done. Deviations from the plan: the Grid's replay is a button rather than a switch, and the controls live in the chart that was clicked (the others have no controls), which is simpler and keeps one driver; `ChartModel.showAt` returns whether the change was a tick or a rebuild so a following cell can scroll to the newest bar only after a rebuild; the Player's smallest count is 1, so a chart that has no ended bar yet at the moment (a weekly chart before its first week closes) shows nothing and its first step shows the first bar. Replay is not kept between visits, as specified. Suites: vitest and Playwright (replay 5, grid replay 1, plus unit tests for the logic, the model, the Chart Lab, the cell and the grid).
