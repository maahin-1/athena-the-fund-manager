## T6-S1 - P1, R3/R4: shared shutdown silently omits direct command owners

Locations: terminal/src/bounded.rs:1732, :1788, :2059, :2075, :2191.

Admission implements PoolView but inherits its default no-op shutdown. WorkRegistry::shutdown_all therefore does not close direct admissions, signal their detached owner tasks, wait for their children, or report/journal unconfirmed exits. The comment that an admission has nothing to end is now obsolete: it owns direct children.

Failing probe: start an immortal FakeDirect under an Admission, register it with WorkRegistry, invoke shutdown_all. The report says unconfirmed=0 instead of 1; no direct cleanup is attempted. This is graceful shutdown, not the documented abrupt-parent-crash limit. Runtime teardown can discard the owner while its child was never journalled.

Fix: admissions need explicit shutdown state and tracked owner completion. Stop admission, handle running direct owners, confirm child exits or persist their unresolved identities, and include them in the aggregate report. Test active, idle/empty, already-held, failed-termination and subsequent-admission paths.

## T6-S2 - P1, R4: partial resolution after an admission resize releases excess capacity

Locations: bounded.rs:1989 and :2211.

Restoring more held children than configured places assigns forgotten semaphore permits only to the first N held records. Resolving those particular records returns their permits without reassigning reservations to the overflow records. Once held.len() falls below running, admission accepts all returned permits even though an unresolved child still occupies part of the intended capacity.

Failing probe: restore 3 held entries into an admission with 2 places; resolve entries 1 and 2. Entry 3 remains unresolved, but two new permits can be acquired. That permits two current commands beside the unresolved child under a two-place limit.

Fix: maintain the invariant that all unresolved records consume capacity or block admission as overflow. Rebalance reservations on every resolution, independent of resolution order and original entry order. Test multiple permutations, reductions, increases and partial clears.

## T6-S3 - P2, R1/R3: an expired direct request can still attempt a spawn

Locations: bounded.rs:2013, :2059, :2066; fundamentals.rs:348; bars.rs:216.

admit has no initial deadline check; run_command also spawns before checking the budget. run_direct recomputes a deadline from now plus remaining duration, and the adjusted-bars path constructs a fresh Budget from a duration passed between layers. An upstream check does not protect all callers or time consumed after that check; export has no corresponding final pre-spawn check.

Failing probe: acquire a valid permit, pass a zero Budget to run_command with a guaranteed nonexistent executable. It returns DirectError::Spawn, proving the spawn was attempted, instead of rejecting expiry first with Timeout. With a real executable this path starts work after expiry.

Fix: preserve one absolute Budget/deadline through the direct-owner and adjusted-bars layers. Check expiry in admission and immediately before spawning, and release the unused permit without starting work. Keep the original absolute deadline when creating the owner. Test zero budget, budget exhausted during admission and elapsed time between argument construction and spawn.

## T6-S4 - P1, R2/R4: ordinary last-owner drop loses unconfirmed idle recovery

Locations: bounded.rs:1279 and :1535.

When the final strong Inner reference disappears, it wakes the worker, which cannot upgrade its Weak reference. The worker attempts termination, but if exit is unconfirmed it again cannot upgrade and therefore cannot retain_idle/persist the process identity.

Failing probe: warm an immortal fake, drop the last Pool owner normally, allow both termination waits to finish, then reconstruct from the journal. New work is accepted instead of the prior child being quarantined.

Claude disclosed this limit. It is still a gap in the normal lifetime/recovery contract, distinct from a terminal crash and from process-tree ownership. main calling shutdown_all protects that call path but does not make Pool/Ticket lifetime handling safe generally.

Fix: make cleanup/recovery ownership outlive the public Pool/Ticket handles until exit or durable retention. A small independent cleanup owner can hold the necessary identity and journal state without an idle worker retaining the entire pool forever. Keep the existing explicit shutdown behavior.

## T6-S5 - safety policy decision, R4: known journal write failure still permits admission

Locations: bounded.rs:1106 and :1299.

A failed persistence operation only sets journal.error. It does not block admission, retry saving without another state transition, or require an acknowledgement. In-memory held workers remain protected, but the recovery record may be absent or stale.

Failing policy probe: make the next journal write fail, let one of two workers become held, verify journal.error is set, then enqueue more work. Admission succeeds. This is disclosed behavior, not an undisclosed implementation surprise.

Recommendation/decision: yes, block new admission while unresolved ownership is known to be undurable. Provide a retry-persist path that does not depend on admitting another job; unblock only after the current full held set is saved or an explicit recorded operator override. Apply the same policy to direct admissions.

Blocking additional admission alone cannot reconstruct a record already lost at a crash. Keep that durability limit explicit; stronger crash guarantees require a durable pre-launch ownership protocol or OS ownership, and are a separate enhancement. Do not represent a status-only write error as durable recovery.

## Responses to the three decisions

1. Keep the existing overall deadline for abandoned running analysis for this slice. A shorter orphan budget is an optional later load policy; measure contention before adding another threshold. Queued abandonment should still cancel.
2. An operator cancellation route is useful but optional and can be deferred. If added later, scope by pool plus job ID, record operator/reason and distinguish requested cancellation from confirmed exit. It does not substitute for automatic cleanup/shutdown.
3. Fail closed on a known failed write of unresolved ownership, as specified above. This is required to avoid silently continuing under a known broken recovery guard.
