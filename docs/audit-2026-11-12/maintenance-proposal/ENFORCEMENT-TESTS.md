# Enforcement tests (proposal; none has been run; 15 tests after review 3)

These are the **negative and behavioural tests** that turn a configured control into a verified one. They run only in the authorized GitHub verification phase, on **disposable branches and disposable protected targets**, never first on `main`. During preparation nothing was pushed, no PR or issue was opened, and no setting was changed.

Rules for every test: record date, responsible maintainer, the exact objects used (branch, PR, run URL) and the effective setting export; save the evidence beside the result; use synthetic content only (never a real credential, even to test push protection: use a provider-approved non-functional pattern); stop and report if a test would touch `main`, real data or a real secret. A control is "behaviour verified" only after its test here has been seen to **block** what it should and **allow** what it should.

## Recording the status of each control

For each control row in [SETTINGS-MATRIX.md](SETTINGS-MATRIX.md) keep one line: `planned`, `local configuration verified`, `GitHub applied`, `behaviour verified`, or `unavailable: <reason>`, with date, run or export reference and the responsible maintainer. A bootstrap exception or the solo-maintainer exception stays listed until it is removed.
