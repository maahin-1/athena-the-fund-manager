## T6-U1 - P2: concurrent shutdown callers can wait forever

Locations: terminal/src/bounded.rs:2001 (OwnerGuard::drop) and :2225 (Admission::shutdown).

Two shutdown futures can both observe owners > 0 and wait on settled. The final owner uses notify_one(), so only one shutdown waiter is released. The other remains asleep even though owners is now zero. Sequential idempotence does not cover concurrent callers.

Independent failing probe: start a fake direct child; join two concurrent shutdown calls under a bounded 20-second fake-clock timeout. The child exits, but the combined shutdown does not finish.

Correction: publish a reusable completion state/broadcast that every shutdown caller can observe. Make waiter registration race-safe as well: replacing notify_one with notify_waiters alone can introduce a check/subscribe lost-wakeup window. Review the analogous all_exited completion in Pool too (not independently probed here).

Acceptance: concurrent shutdown before/after final exit, an already-completed shutdown, empty pool, confirmed exit and unconfirmed journalled exit. All callers finish and observe a consistent report.

## T6-U2 - P2: shutdown undercounts a child already in timeout cleanup

Locations: bounded.rs:2282-2353 (direct_owner, deadline path), :2225.

If the request times out first, its owner enters end_direct. When shutdown starts during that cleanup and the child is then confirmed gone, the owner drops its permit and returns without note_end_at_shutdown. Shutdown correctly waits for the owner but reports zero ended children.

Independent failing probe: request deadline at t=10; termination confirms at t=13; invoke shutdown at t=11. Exit is in the fake log, but report.ended is 0 instead of 1.

Correction: use one once-only accounting path for owner exit while closing, independent of whether the original trigger was timeout or shutdown. Do not double count when shutdown observes a child already ending.

Acceptance: deadline-before-shutdown and shutdown-before-deadline, with confirmed and unconfirmed endings; report matches owned children dealt with during shutdown.

## T6-U3 - P2: direct admission omits its documented journal.blocking field

Location: bounded.rs:2437 (Admission::status).

Pool::status supplies journal.blocking, but Admission::status still supplies only journal.enabled and journal.error. The implemented admission correctly refuses work after an undurable hold; the advertised diagnostic field is missing.

Independent failing probe: fail a direct hold's journal write; admission returns Held, journal.error exists, but journal.blocking is null rather than true.

Correction: emit the same blocking contract for pools and direct admissions, with behavior-derived tests. Test true for held + failed write, false for an error with nothing held, and false again after successful retry. Verify the WorkRegistry payload, not only a hand-written fixture.

## T6-U4 - P2: source-inspected startup/shutdown registration race

Locations: bounded.rs:2019, :2225, :2250 and :2258.

run_command checks closed under a short state lock, releases it, spawns the process, then registers its OwnerGuard through run_direct. A legal multithread interleaving is:

1. command sees closed=false;
2. shutdown sets closed=true, sees owners=0, and returns;
3. command spawns and only then registers its owner.

The later owner will attempt cleanup, but a shutdown report has already escaped and runtime teardown can interrupt it. This is different from the explicitly documented low-level run_direct handoff after shutdown: the managed run_command API itself passed through the race.

This interleaving was identified in source, not reproduced with a runtime barrier. Normal main shuts down after draining HTTP handlers, which narrows that particular call path; do not claim this happens on every terminal exit.

Correction: add a controlled multithread regression first. Serialize the startup decision and in-flight owner reservation against shutdown. A shutdown racing a start must either reject the launch or count/wait for it. If the strict contract is that no launch occurs after closure, include the actual spawn boundary in the synchronization design. Roll back reservations on spawn failure. Preserve cleanup for pre-spawned children handed to the low-level API.
